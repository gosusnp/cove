# Style Guide

Naming, formatting, and file conventions for the Cove codebase.

---

## File Headers

Every source file begins with a copyright and license header.

**Go:**
```go
// Copyright (c) 2026 Jimmy Ma
// SPDX-License-Identifier: Elastic-2.0
```

**SQL:**
```sql
-- Copyright (c) 2026 Jimmy Ma
-- SPDX-License-Identifier: Elastic-2.0
```

**JSX/JS:**
```js
// Copyright (c) 2026 Jimmy Ma
// SPDX-License-Identifier: Elastic-2.0
```

- **DO** add the header to every new file before any other content.
- **DON'T** omit the header because "it's just a config file" or "it's autogenerated."

## Backend (Go)

### File Names

- **DO** use `snake_case.go`: `program_exercises.go`, `user_sessions.go`
- **DON'T** use camelCase or PascalCase filenames: ~~`programExercises.go`~~, ~~`UserSessions.go`~~
- **DO** suffix test files with `_test.go` in the same package: `exercises_test.go`
- **DON'T** create a separate `tests/` directory for Go tests.

### Package Names

- **DO** match the package name to its directory: `package handlers`, `package service`, `package store`
- **DON'T** use plural packages or mismatched names: ~~`package handler`~~, ~~`package services`~~

### Identifiers

| Kind | Convention | Example |
|---|---|---|
| Exported functions/methods | `PascalCase` | `NewExerciseHandler`, `RegisterRoutes` |
| Unexported functions/methods | `camelCase` | `list`, `create`, `normalizeName` |
| Exported struct fields | `PascalCase` | `Name string`, `ExerciseID int64` |
| Unexported struct fields | `camelCase` | `svc`, `db`, `store` |
| Request DTOs | unexported struct | `type exerciseRequest struct` |
| Receiver names | single letter | `(h *ExerciseHandler)`, `(s *ExerciseStore)` |

- **DO** use a single-letter receiver name derived from the type: `h` for handler, `s` for service/store.
- **DON'T** use `self`, `this`, or the full type name as a receiver: ~~`(handler *ExerciseHandler)`~~

### JSON Tags

- **DO** use `snake_case` for all JSON tags: `` `json:"exercise_id"` ``, `` `json:"intra_set_rest_seconds"` ``
- **DO** use `omitempty` with pointer fields for optional data: `` `json:"progression,omitempty"` ``
- **DON'T** use camelCase JSON tags: ~~`` `json:"exerciseId"` ``~~
- **DON'T** omit `omitempty` on pointer fields — it will serialize `null` instead of omitting the key.

### Environment Variables

- **DO** use `UPPER_SNAKE_CASE`: `DATABASE_URL`, `GOOGLE_CLIENT_ID`
- **DON'T** use any other casing for env vars.

### Comments

- **DO** start comments with a capital letter and end with a period: `// OAuth guards routes by validating Bearer tokens.`
- **DON'T** write lowercase or unpunctuated comments on exported symbols.

## Database

### Migration Files

**Pattern:** `NNN_description.up.sql` / `NNN_description.down.sql`

- **DO** use a 3-digit zero-padded number: `001_`, `002_`, `010_`
- **DO** write a short, descriptive snake_case name: `001_initial_schema`, `002_auth`
- **DON'T** skip the down migration — every up must have a matching down.
- **DON'T** edit existing migration files. Create a new numbered migration instead.

### SQL Conventions

- **DO** use `BIGSERIAL PRIMARY KEY` for auto-increment integer PKs.
- **DO** use `UUID PRIMARY KEY` for user/org identity tables.
- **DO** use `CITEXT` (case-insensitive text) for user-facing unique identifiers like `email` and `name`.
- **DO** use `TIMESTAMPTZ` for all timestamp columns.
- **DO** use `NUMERIC(p,s)` for decimal values like weights: `NUMERIC(5,2)`.
- **DON'T** use `VARCHAR(n)` — prefer `TEXT` or `CITEXT`.
- **DON'T** store timestamps as `TIMESTAMP` without timezone.

## Frontend (Preact/JSX)

### File Names

| File type | Convention | Example |
|---|---|---|
| Components | `PascalCase.jsx` | `WorkoutTracker.jsx`, `ExerciseCard.jsx` |
| Hooks | `camelCase.js` | `useExercises.js`, `useAuth.js` |
| Utils / helpers | `camelCase.js` | `formatDuration.js`, `api.js` |
| Stylesheets | `kebab-case.css` | `app.css` |
| Entry / setup | lowercase | `main.jsx`, `test-setup.js` |

- **DON'T** use `camelCase.jsx` for component files: ~~`workoutTracker.jsx`~~, ~~`exerciseCard.jsx`~~
- **DON'T** use `PascalCase` for hooks or utils: ~~`UseExercises.js`~~, ~~`FormatDuration.js`~~

### JSX Attributes

- **DO** use `class=` for HTML class attributes in Preact JSX.
- **DON'T** use `className=` — that is the React convention, not Preact.

```jsx
// DO
<div class="flex gap-3 items-center">

// DON'T
<div className="flex gap-3 items-center">
```

**Exception — Radix `asChild` children:** when an element is passed as the child of a Radix component using `asChild`, it is processed by Radix's Slot which merges props using the React `className` convention. Use `className=` on those elements only.

```jsx
// Inside a ui/ component wrapping Radix with asChild — use className=
<RadixDialog.Trigger asChild>
  <a href={href} className={styles}>…</a>
</RadixDialog.Trigger>
```

### Styling

- **DO** use Tailwind utility classes for layout, spacing, and typography.
- **DO** reference design tokens via CSS variables in `style` props or `var()` in CSS files.
- **DON'T** hardcode color hex values in JSX — use `var(--color-*)` tokens.
- **DON'T** create new CSS variables without adding them to the `:root` block in `app.css`.

```jsx
// DO
<p class="text-sm" style={{ color: "var(--color-muted)" }}>

// DON'T
<p style={{ color: "#4a6491", fontSize: "14px" }}>
```

### Component Exports

- **DO** use named exports for components: `export function App() {}`
- **DON'T** use default exports for components: ~~`export default function App() {}`~~

### UI Components (Gold Standard)

All interactive and reusable UI elements must come from `src/components/ui/`. These are the gold standard primitives for the entire frontend. **Do not build one-off buttons, dialogs, inputs, or navigation elements inline.**

| Component | File | Description |
|---|---|---|
| `Button` | `components/ui/Button.jsx` | 3 variants (`primary`, `outline`, `ghost`), 3 sizes (`sm`, `md`, `lg`) |
| `Dialog` + sub-components | `components/ui/Dialog.jsx` | Modal dialog; open state managed via signal |
| `Switch` | `components/ui/Switch.jsx` | Toggle; accepts optional `checkedSignal` |
| `NavigationMenu`, `NavigationMenuItem`, `NavigationMenuLink`, `NavigationMenuBrand` | `components/ui/NavigationMenu.jsx` | Accessible nav links via Radix |
| `TopBar` | `components/ui/TopBar.jsx` | Fixed desktop top navigation shell |
| `Avatar` | `components/ui/Avatar.jsx` | User initials avatar; `label` prop sets `aria-label` |
| `TextField` | `components/ui/TextField.jsx` | Text input; optional `label` prop; supports `disabled` and `readOnly` |
| `Tooltip`, `TooltipTrigger`, `TooltipContent` | `components/ui/Tooltip.jsx` | Hover tooltip; wraps Radix; self-contained provider |
| `Section`, `Row`, `Divider` | `components/ui/Section.jsx` | Page section card with title; labeled row with right-side slot; `last` prop on `Row` drops the bottom border |

Supporting utilities:

| Path | Description |
|---|---|
| `src/lib/utils.js` | `cn()` — class merging via clsx + tailwind-merge |
| `src/hooks/useDialog.js` | `useDialog(initialOpen?)` — signal-based dialog state |

Rules:

- **DO** use `src/components/ui/` primitives for all interactive elements.
- **DO** extend an existing primitive (via props or a wrapper) before creating a new one.
- **DON'T** write raw `<button>`, `<a>`-as-button, or custom modal markup outside of `ui/`.
- **DON'T** add a new `ui/` component without a corresponding section in `/design-elements`.

The `/design-elements` route (visible when `VITE_COVE_ENV=dev`) is the live showcase for all `ui/` components. Every primitive must be represented there with all meaningful states (variants, sizes, disabled, active, etc.).

### Testing UI Components

Radix UI packages use browser APIs (`ResizeObserver`, CSS custom properties) that jsdom does not support. Any Radix package that causes `InvalidCharacterError` in tests must have a jsdom-compatible mock in `src/__mocks__/`.

The mock is wired via a vitest-only alias in `vite.config.js`:

```js
test: {
  alias: {
    "@radix-ui/react-navigation-menu": resolve(import.meta.dirname, "src/__mocks__/radix-navigation-menu.jsx"),
  },
}
```

- **DO** add a mock to `src/__mocks__/` for any new Radix package that breaks tests.
- **DO** keep mocks minimal — passthrough components that render children are enough.
- **DON'T** add the alias to the main Vite config — only inside the `test` block.
